# Gate 0 — the plugin name and slug

**Run this before writing a line of compliance work.** The slug is derived from the
`Plugin Name` header at submission, sanitised like a post name (a clash silently appends
`-2`). It can be changed **once, before review begins, and never after approval**. A name
problem found after approval cannot be fixed — only re-submitted as a new plugin, losing
every install.

Two different systems judge the name, and **passing one is not passing the other**:

| | What it inspects | What happens on a hit |
|---|---|---|
| `Trademarks_Check` (code) | readme name, header name, **slug** | Emits `trademarked_term` as a **WARNING** — it does *not* block the upload form |
| The Plugins Team's AI pre-review + a human | display name, slug, short description, readme | Rejection email |

**A clean Plugin Check run tells you nothing about the name.** `trademarked_term` is a
warning, and warnings do not block the upload. The rejection arrives later, from a person.

---

## 1. Banned terms — no context makes them acceptable

Not fixable by placement, by "for X", or by abbreviation. Remove them.

**Meta** — their legal representatives told wordpress.org directly that the wordmark may
not appear in a display name, slug or banner:
Facebook (incl. `FB`, `fbook`) · WhatsApp (incl. `WA`, `Whats`, `Whats App`, `vvhatsapp`,
`vva`, `wh4tsapps`) · Instagram (incl. `Insta`, `Gram`, `INS`) · Threads · Oculus

**WordPress Foundation** — WordPress, `wpress`, `wordpess`; and `WP` as a standalone word,
including the trailing `for WP` / `for WordPress` construction. You are publishing *in the
WordPress plugin directory*; saying so is redundant.
`PRT Text editor for WP` → `PRT Text editor`.

**Other:** Trustpilot · Binance Pay

## 2. Discouraged terms — remove them, there is no compliant placement

- **`Plugin`** — when it only says "this is a plugin" (`SEO Plugin`). Forbidden as the
  first word.
- **Superlatives** — `best`, `#1`, `First`, `Perfect`, `The Most`. Also banned in the
  readme body: claiming to be better than, or the only, solution is treated as dishonest.
- **`Free`** — redundant in a directory of free plugins.
- **`WP`** at the beginning or end, `W P`.
- **`Gutenberg`** and fragments (`gberg`, `guten`, `berg`) — the editor is called the
  *block editor*; Gutenberg is the beta channel, so the name causes confusion.

## 3. Everyone else's trademarks — placement is the whole rule

Allowed **only at the end**, after a structure that denies affiliation: `for`, `with`.
Several: `… for TRADEMARK1 with TRADEMARK2`.

| Name | Verdict |
|---|---|
| `WooCommerce Pricing Rates` | ✗ reads as an official WooCommerce plugin |
| `Paypal Payment Gateway for WooCommerce` | ✗ leads with someone else's trademark |
| `Nicedev Paypal for WooCommerce` | ✗ distinctive term first, but Paypal still isn't behind `for`/`with` |
| `Nicedev Payment Gateway with Paypal for WooCommerce` | ✓ |
| `Pricing Rates for WooCommerce` | ✓ |
| `Pricing Rates` | ✓ no trademark at all |
| `Bank of Germany Pricing Rates` | ✗ implies an official institution |
| `PricingPress` | ✗ portmanteau on the WordPress trademark |
| `Locaki` | ⚠ looks original, but may be someone else's unregistered mark — expect to justify it |

**An unfamiliar-looking coined word counts as a trademark to be checked.** If it is
*yours* (your company, your domain, your username) it is fine — that is the recommended
way to make a generic name distinctive.

## 4. Too generic

A name must say **what it does** *and* **in what context**. For "shipping tracker for UPS,
integrated with WooCommerce":

`Shipping` ✗ · `Ecommerce Shipping` ✗ (no context) · `Shipping Tracker for UPS` ✓ ·
`ShipGlex Shipping` ✓ (coined term)

The coined term must come **first**, never appended at the end.

## 5. Keyword stuffing

Unnatural repetition of a keyword in the display name, short description, readme or tags.
Judged on the display name especially.

### How the matching works

`Trademarks_Check::has_trademarked_slug()` walks `TRADEMARK_SLUGS`. An entry ending in
`-` is a **prefix** test — the slug may not *begin* with it. An entry with **no** trailing
hyphen is a `strpos` test — the term may not appear in **any** position.

This is why `wp` being a bare entry refuses `html2wp-editor`, `my-wp-tools` and anything
else carrying `wp` anywhere in the slug, regardless of what the product is called.

### The `-for-` escape hatch is narrower than everyone believes

`is_valid_for_use_exception()` applies **only** to trademarks listed in
`FOR_USE_EXCEPTIONS`, and that list currently holds exactly one entry. For anything else,
`…-for-<trademark>` in the slug does **not** help.

Even for an eligible term the test is two-stage: the slug must contain one of the accepted
patterns, **and** after that pattern is removed the term must not appear anywhere else.

```
mcp-for-woocommerce        -> '-for-woocommerce' found, remainder 'mcp'        -> OK
woo-mcp-for-woocommerce    -> pattern found, remainder 'woo-mcp' contains woo  -> refused
woocommerce-shipping       -> no pattern                                        -> refused
```

`PORTMANTEAUS` separately blocks blends built on a trademark (`woopress`).

## 7. Similar names

Run `scripts/name-check.sh "<display name>" [<slug>]`. It greps the lists above and then
queries the directory:

```
https://api.wordpress.org/plugins/info/1.2/?action=query_plugins&request[search]=<name>
https://api.wordpress.org/plugins/info/1.2/?action=plugin_information&request[slug]=<slug>
```

Judge the results the way the reviewer does:

- Weight plugins with **>10,000 active installs** or a strong public presence.
- "Confusing" = an ordinary user would mix the two up **from the name alone**.
- Common functional terms (`SEO`, `Payment Gateway for WooCommerce`) are *not* by
  themselves confusing — the distinctive component is what matters.
- Same functionality under a clearly different name is **not** confusing.

**A trap:** searching for a name that is not in the directory yet returns fuzzy matches
from large plugins. That looks exactly like "your name loses" and is evidence of nothing.
Only compare against plugins that actually exist.

## 8. Output when Gate 0 fails

Match the shape of the real rejection email — state the problem, then a compliant
alternative:

```
possible_naming_issues: true
naming_explanation:     <why, in one or two sentences — the problem, not the fix>
trademarks_found:       [<terms detected in the display name>]
suggested_display_name: <compliant name>
suggested_slug:         <derived, lowercase, hyphens, ≤50 chars, no banned term anywhere>
```

Rules for the suggestion: never include a banned or discouraged term (so never "WordPress"
or "WP"); put any third-party trademark at the end behind `for`/`with`; lead with a
distinctive term — the author's brand, company or a coined word — if the remainder would
be generic; and do not land close to an existing high-install plugin.

## 9. Naming for discoverability (once compliance is settled)

An exact phrase **in the title** wins that phrase almost regardless of install count — a
200-install plugin outranks a 10M-install one for a phrase its own title contains. So:

1. **Title** is the highest-weighted field. `Brand – what it does` is the standard shape.
   But the slug is derived from `Plugin Name` **at submission**: submit with the short
   name to get a short slug, then extend the display name afterwards. Header and readme
   `=== … ===` must always match; the slug never changes again.
2. **Five tags, and only five.** A tag owned by a 10M-install plugin buys nothing.
3. **Short description** — indexed, and it is the line a person actually reads. ≤150 chars.
4. **`Tested up to` at the current major** — an outdated value hides the plugin from search.
5. **`icon-128x128.png`** shows in the results list, so it decides the click.
